B+treeeach key's newest version

4 KiB slotted pages

A 48-byte header, 12-byte slots in key order, keys and values in a heap growing from the end. Fence keys bound each page; a shared prefix is stored once.

Optimistic latches

A reader checks a page's version instead of taking its latch; after two refused tries it holds the leaf shared.

Right links

Each leaf names its right neighbour, so a scan walks the leaf level.

Buffer poolpages in memory

Frames

A fixed array of 4 KiB frames, split into up to 64 partitions; each worker's version tree has a pool of its own.

Predictive translation

Page id to frame through a table, with the preferred frame read while the table is probed.

Cooling and in-flight reads

With no frame free, pages are sampled into a cooling queue; a miss is one read, shared by threads that need the page.

Reading a key

A hit, a miss, and a full pool

At every level a lookup searches the page, checks that no writer changed it, and turns the child's page id into the frame that holds it.

1 · hit

The page is in memory

The preferred frame, computed from the id, is read while the translation table is probed. If the table names that frame and the frame still holds the page, the hit has taken no lock.

2 · miss

One read

The first thread to miss claims the page's row in the in-flight table and issues one 4 KiB read; a second thread missing on it waits on that row. The CRC-32C over the page id and the bytes is checked before the table names the page.

3 · pool full

Cool, then evict

When no frame is free, the thread that missed samples hot pages into a cooling queue (about 10% of the pool). A cooling page that is touched warms back without a read; only pages that reach the old end untouched are evicted, a changed one written first, after its log records are durable.

Committing

Pre-commit, then acknowledgement

A version names its writer by worker and start timestamp, so committing rewrites no version: pre-commit appends one log record, takes one clock tick and adds one entry to the worker's list of commits.

1 · write

insert / remove

The version it replaces moves to the worker's own version tree; the new version is installed under the leaf's exclusive latch, then one change record is appended to the worker's log ring (a split logs its own record before it). A write over a version the snapshot cannot see is refused with Conflict.

2 · pre-commit

Visible, worker free

The commit record is appended, a commit timestamp is taken from the clock, and one entry in the worker's list of commits publishes every version the transaction wrote. The worker is free for the next transaction at once.

3 · acknowledgement

Durable when it returns

The client waits until its own record is durable, other workers' logs are durable up to the changes its pages depend on, and every transaction it read from or wrote over is acknowledged. One shared barrier makes the finished ring writes durable.

With Durability::Eventual a commit is answered once its records, and those it depends on, are written, while its worker's undurable log stays under 1 MiB by default; a page is still never written ahead of its log.

Values of any size

Three homes for a value

The thresholds count the stored value, which carries a 19-byte version header in front of the client's bytes.

in the leaf

Small values

A value stays in its leaf unless its entry (key, stored value and 12-byte slot) takes more than 506 bytes, an eighth of the page's 4,048-byte data area, and the stored value is at least half of that.

a value page

Larger values

A value whose entry passes 506 bytes and whose stored value is 253 bytes or more (234 of the client's) moves to a value page that packs several values. The leaf keeps an 8-byte reference and the 11 bytes a snapshot needs to decide visibility.

a run of pages

Past the data area

A value whose entry would not fit in 4,048 bytes becomes one contiguous run of pages, kept out of the log and read up to 256 pages (1 MiB) at a time.
